四、协议速览
  
现在的控制码是两套通道：client ↔ server 走 TCP 协议码，浏览器 ↔ server 走 HTTP API。浏览器不直接发协议码，它操作 server 本地的图像源；client 才发协议码。
1. 协议帧（common\protocol.h）
固定 16 字节头 FrameHeader："CAM0"(4) + ctl控制码(4) + err错误码(4) + len数据长度(4)，本机小端直接 memcpy。
"头+数据"合并成一次 bufferevent_write，保证一个包完整发出。
2. 控制码表（Ctl，共 8 个）
码	方向	含义
1 HeartbeatReq	client→server	请求心跳
2 HeartbeatResp	server→client	心跳应答，带 4 字节时间戳
3 ReqImage	client→server	开始收图
4 StopImage	client→server	停止收图
5 ImgData	server→client	图像数据（16 头 + 640×480 灰度）
6 CtrlDev	client→server	设备控制（未实现，回错误码 4）
7 PauseSource	client→server	全局冻结图像源
8 ResumeSource	client→server	恢复图像源

错误码 4 个：Ok、ImgTimeout（5 秒没新图）、ServerFull、UnknownCtl。
3. server 端解析（client_session.cpp 的 onRead）
循环按 16 字节读头 → 校验 "CAM0" → switch(ctl)：HeartbeatReq → 回 HeartbeatResp + 4 字节毫秒值
ReqImage → 启动发送线程，等新帧，发"头+数据"
StopImage → 停发送线程（唤醒 + join）
PauseSource/ResumeSource → 直接调 ImageSource::pause()/resume()，全局冻结（所有客户端一起冻，恢复从原位置继续）
未知码 → 回 UnknownCtl

4. client 端状态机（client.cpp）
三态：WaitHb → Idle → Image。连上先发心跳等应答，通过后进 Idle。
按键 s → 发 ResumeSource + ReqImage 进收图态；按键 q → 发 StopImage + PauseSource 回 Idle；h 手动心跳；Idle 下每 3 秒自动心跳。
收图态只认 ImgData，收到别的码直接重连。
5. 浏览器端（web_server.cpp 的 HTTP 路由，不经协议码）
/api/start → source_->resume()，/api/stop → source_->pause()（和 client 的 7/8 号码操作同一个东西，所以浏览器暂停时 client 看到的图也会冻结）
/api/fps → setIntervalMs() 调帧率，/api/heartbeat → 本地计数，/api/stats → 汇总状态，/api/display → 只记录尺寸，/frame → 输出当前帧 PNG
一句话总结：协议码只管 client↔server 的心跳、收图开关、全局暂停/恢复；浏览器则直接改 server 本地图像源，两者共享同一份"暂停/恢复"状态。


五、超时与重连参数（common\protocol.h 中可调）
  图像生成间隔 100ms（10 帧/秒）
  发送线程等 img_ready 超时 5 秒（超时发 err_code=1 的空头）
  客户端心跳间隔 3 秒；读超时 3 秒
  断线/出错/超时后每 2 秒自动重连

六、实现要点
  · 服务器主线程 evconnlistener 监听；图像生成线程每 100ms 生成一帧并广播
    img_ready（Windows CONDITION_VARIABLE）；每客户端 1 个控制线程
    （独立 event_base + bufferevent）+ 1 个图像发送线程。
  · 线程安全：evthread_use_windows_threads()；每客户端发送加锁，保证
    "16 字节头 + 图像数据"不被打断；共享图像缓冲在锁内拷贝。
  · 客户端单线程事件循环 + 键盘输入线程（event_active 跨线程通知）；
    收包用"先收 16 字节头、再按 nDataLen 收载荷"的状态机。


整体架构

共同基础：一套 16 字节协议头（common/protocol.h）
结构：flag[4]="CAM0" + ctl_code + err_code + nDataLen，正好 16 字节
控制码：1 心跳请求 / 2 心跳应答 / 3 请求图像 / 4 停止图像 / 5 图像数据 / 6 设备控制
所有数据都按“先 16 字节头、再 nDataLen 字节载荷”的帧格式传输，这是 TCP 流式协议的标准做法，天然兼容粘包/半包
Server（server.cpp）：三类线程
图像生成线程（全局唯一）：高精度定时器每 20ms 生成一帧，写进全局缓冲并广播条件变量（server.cpp:443）
控制线程（每客户端一个）：解析请求、启停发送线程（server.cpp:309）
发送线程（每客户端一个）：等“新帧”信号后把最新一帧发出去（server.cpp:127）
Client（client.cpp）：单线程 + 状态机
所有网络、定时器、键盘动作都在同一个 event_base 里跑，天然线程安全
用 ST_* 状态机管理连接阶段：ST_DISCONNECTED → ST_CONNECTING → ST_IDLE → ST_WAIT_HB/ST_IMAGE
唯一的额外线程是键盘线程，因为 getchar() 阻塞，通过 event_active() 跨线程唤醒主循环（client.cpp:721）
Server 关键点讲解
生产者-消费者模型：g_img_lock + g_img_cond 把生成线程和各客户端的发送线程连起来。生成线程持锁写图、
递增帧序号，发送线程在锁上 SleepConditionVariableCS 等信号。用“帧序号”而不是“标志位”判断有没有新帧，避免丢帧/重复帧
跳帧策略：发送线程只 memcpy“最新一帧”，客户端跟不上就自然跳帧，保证延迟最低；网络发送在锁外进行，某个客户端慢不会卡住生成线程
每客户端独立 event loop：ctrl_thread_main 里每个客户端有自己的 event_base + bufferevent，互不阻塞；配合 evthread_use_windows_threads() 保证 libevent 内部线程安全
send_lock：保证“16 字节头 + 图像数据”这两次 bufferevent_write 之间不被同一客户端的其他发送插队
稳帧的关键：timeBeginPeriod(1) 把系统定时器精度提到 1ms，配合 CreateWaitableTimer 才能稳定 50fps
Client 关键点讲解
收图状态机（read_cb，client.cpp:128 之后的核心）：两阶段解析——先攒够 16 字节头，校验 CAM0 后调 on_header() 分发，再按 nDataLen 收载荷，收齐调 on_payload()。回调里用循环处理“一次到达多个包”
ST_IDLE 丢数据保护：read_cb 开头检查 ST_IDLE 时直接清空输入缓冲——这就是之前“按 q 后非法头标志刷屏、误重连”问题的根源（按 q 时残留半帧数据被当成了协议头）
心跳闭环：空闲每 3 秒发心跳 → ST_WAIT_HB → 应答后回 ST_IDLE 重新计时；3 秒没应答触发读超时 → 断线重连，链路断掉最多 3 秒就能发现
重连去重：g_reconnect_pending 防止断线事件重复触发连开多个定时器
GDI 预览：CreateDIBSection 拿到可直接写像素的内存，灰度展开成 24 位 RGB 后 BitBlt；窗口消息由 10ms 定时器泵，不用单独开 UI 线程
每个 client 独立保存目录：frames_时间_PID，多个客户端各存各的

二、class 类划分（为什么这样拆）
--------------------------------------------------------------------------------
拆类原则：按"核心业务实体"划分，每个类一个 .h（声明）+ .cpp（实现），
头文件用 #pragma once；构造/析构负责资源申请与释放（RAII）；
动态内存全部由 std::vector / std::unique_ptr / std::thread 管理，无裸 new/delete。

  PngEncoder      纯工具类：灰度 → PNG 编码，无外部依赖，便于复用/单测
  ImageSource     图像生产方：唯一写图线程，广播"新帧"信号；暂停=全局冻结
  ClientSession   单个 TCP 连接：接收控制命令、启停发送线程、断开后自清理
  ClientManager   会话容器：表满拒绝、计数、会话销毁入口（线程安全）
  WebServer       浏览器界面：独立线程轮询 mg_mgr，不阻塞主监听循环
  Server          组合根：组装上面所有对象，主循环监听 9995
  Client          客户端状态机：心跳/收图/重连/按键全在一个事件循环
  PreviewWindow   预览窗口：把 GDI 细节全部封装，Linux 下自动空实现
